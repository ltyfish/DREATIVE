# Audit — 2026-10-01

Scope: the whole Dreative skill (instructions, CLI, resourcing, motion tooling) and the
testbed, judged against the goal: help Claude Code, Codex and similar agents plan,
resource and build distinctive, motion-led, award-calibre sites.

## Why results stopped improving

Evidence: latest judged run `clothing-motion__with-a__202609180358` (2/5), its
`design-blocker.md`, `reads.json`, captures and source; DECISIONS history.

1. **Missing capability, mislabelled as missing guidance.** Claude Code has no image
   generator, and no key was set. The agent spent its exploration on a 24-query archive
   sweep and HTML mockups, then shipped polygon garment outlines filled with cloth
   texture. Subject imagery decides most of a commerce page's quality. For weeks the
   skill's prose was revised against a tool gap that prose cannot close.
2. **The motion stack was all friction.** Runs share a `node_modules` that had no
   GSAP or Lenis. The skill also steered agents to hand-written native foundations and
   called Lenis "not a default". The run hand-rolled IntersectionObserver + rAF.
   Award-level motion is mostly a well-tuned GSAP/ScrollTrigger/SplitText/Flip/Lenis
   stack, and agents never got working, tuned starting code for it.
3. **The instructions were mostly prohibitions.** Core files average about one
   negation per 50–60 words (SKILL 29, MEDIA_SOURCES 35, VISUAL_DESIGN 27). They held
   almost no concrete timing, easing or code (SKILL: 4 such lines). Every failed round
   added another caveat, so agents got a fog of constraints and few moves to make.
4. **The rules that mattered sat behind pointers that weren't read.** The run opened
   `PLAN.md`, `MEDIA_SOURCES.md` and `VISUAL_DESIGN.md` only. It never opened
   `skills/motion.md` or `CHOREOGRAPHY.md` on a motion-led brief. This matches DL-017,
   DL-020 and DL-022.
5. **The evaluation loop confounds too much.** It uses one subject, one human 1–5 score
   per round, and several variables changed per round. Material availability was the
   dominant variable and it was never controlled until the supplied-assets scenario.

## What changed (Dreative 1.6.0)

- `dreative media probe | generate | search`. Generation goes through OpenAI, Gemini,
  fal, Replicate or the host's own tool. `--ref` gives views of the same subject
  (OpenAI/Gemini). The keyless fallback is labelled exploration-only. Search covers
  Openverse without a key and Pexels/Unsplash/Pixabay with keys. Bytes are checked as
  real images, and provenance/licence manifests plus a contact sheet are written.
  Tests: 7 mocked unit tests. Run live from this machine: probe, keyless generation and
  Openverse search worked. The keyed providers have not been called live (no keys here).
- `references/MOTION_RECIPES.md`: R0 setup (Lenis on the GSAP ticker, matchMedia,
  React/Vue notes), timing/easing tokens, and ten recipes. Covered: masked line reveal,
  clip reveal, framed parallax, pinned labelled timeline, horizontal rail, Flip handoff,
  velocity marquee, readiness loader, stacked sheets, pointer craft. Also composition
  patterns and pitfalls. The same code runs in `systems/motion-recipes.html`. Six
  Playwright tests cover it at desktop, mobile and reduced motion, with Lenis wheel
  input. Looking at the screenshots found a clipped-descender bug in masked lines that
  the tests had missed; it is now fixed in the recipe.
- `SKILL.md` is now an ordered procedure. It carries the material rules and motion
  stack rule inline, along with the commands for each step and a short list of craft
  reference points. `PLAN.md` treats directions as generated compositions or as coded
  studies built with real material. A selected study becomes production code, not a
  throwaway mockup.
- Testbed: `gsap` and `lenis` are installed for both arms (root and run template).
  Setup reports image-generation readiness. The skill is reinstalled exactly for Claude
  and Codex.

Unchanged on purpose: the selection gate, the finalize contract, honest reporting, and
"no taste gates, effect quotas or read-count enforcement".

## What still limits quality

- Without a keyed generator, subject-led briefs get exploration-grade imagery at best.
  Set one key in the testbed environment (both arms inherit it) or use
  `clothing-motion-supplied`.
- Nothing here is creative-quality evidence. The next judged round is the test.
- Codex discovery: the installer writes `.codex/skills` plus an AGENTS.md pointer.
  Check the current Codex skill directory convention when Codex is next updated.
