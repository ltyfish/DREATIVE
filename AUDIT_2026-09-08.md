# Dreative audit — 8 September 2026

The skill now helps an agent create a convincing individual motion idea, but
does not yet reliably produce a complete, convincingly art-directed experience.
The highest-value investment is material production and composition across the
journey. Adding more effects or enforcement would miss the failure shown here.

## Findings, in priority order

### 1. Material access failures became the art direction

The builder searched Unsplash/Pexels and open-license endpoints, encountered
access or fit problems, then synthesized fabric and composited it into garment
shapes. The recorded tool searches requested browser tools; they do not establish
that image/video generation capabilities were explored or available. A Pixabay
request used `key=test`, which cannot establish usable access. Do not infer that
the Codex tools available in this audit existed in that Claude build.

The nine 1200×1600 images are coherent in light and frontal framing, but that
coherence multiplies weak shape and construction. The trousers are nearly flat
rectangular cutouts; the outerwear has simplified collars and depth. The same
kind of view carries discovery, hero, and commerce, with no meaningful context
or alternate-shot family. A cloth shader can be compelling while the object
revealed by it remains unconvincing.

Recommendation implemented: discover callable authoring and sourcing routes,
classify access failures, and inspect one representative object before producing
a set. Choose overview/detail/context views according to their job. Use an
actual generated or sourced subject when warranted; procedural textures do not
constitute a photographic pipeline. Fictional inventory permits representative
concept imagery, but still requires visual credibility.

### 2. The successful slice did not become a complete sequence

The opening carries a cloth-to-garment idea into a row. The rest of the source
then maps content into a shop grid, size table, care rows, delivery rows, review
cards, about facts, and footer. Most use one shared `.reveal` treatment. The
shader also resolves product images, so it would be inaccurate to say there is
no motion below the hero. The problem is that the information and composition
barely develop through that motion.

The user explicitly requested memorability beyond the hero in the brief. This
is not explained by a mismatch between an ordinary shopping brief and an
unexpected demand for spectacle. The existing documents mention continuity,
but procedural effect instructions are more actionable than the guidance for
turning required content into an experience.

Recommendation implemented: a conditional choreography guide at slice expansion.
It teaches outgoing/carrier/incoming relationships, typography making space for
imagery, image-to-detail transitions, claims supported by visible details,
collection rearrangement, explicit holds, and a resolved ending. Required facts
remain available without requiring one section per source array. No quotas,
mandatory extra hero, forced five-act story, or universal apparel template.

### 3. Practical UX became a conventional presentation by default

The controls and detailed content are useful. However, every garment receives
much the same presentation, and supporting information mostly becomes a table
or repeated row. Usability does not require that exact arrangement. Image-led
exploration, contextual detail, measurement annotations, and selection transitions
can support the practical task when the underlying semantics stay familiar.

Recommendation implemented: compare expressive and direct presentations against
the real content and action. Preserve selection, item identity, focus, return
position, and accessible fact retrieval through animation. The rule is not
“replace tables”; tables may remain the best comparison surface.

### 4. Palette, scale and the ending lack development

The full-page image repeats pale neutral fields, similar heading treatments and
similarly framed merchandise. Lower sections vary background tone more than
they vary composition. The footer contains serviceable copy without much visual
resolution. The mobile sectional image also places substantial empty space
between the garment and caption; a still cannot prove whether the intervening
scroll duration earns it.

Recommendation implemented: evaluate palette against actual material, compare
resolved compositions across the route, tune distance in playback, and give the
ending an explicit composition. The skill supplies relationships and diagnostic
questions instead of a prescribed palette, typography pair or branded house style.

### 5. Capture evidence overstates coverage if only metadata is read

The archived desktop recording lasts about 8.04 seconds. Sampled frames show
missing hero/product imagery, despite separate stills showing it. Its error
array is empty. The mobile JSON explicitly reports `reachedEnd: false`.
These findings do not prove the user's browser showed the same defects; they
prove those recordings cannot certify the whole intended experience.

There is also a concrete source risk: `WeaveGrid` keeps an item active if its
texture never becomes ready; the error handler deletes its loading record but
does not remove it from active work. CSS hides its DOM image until resolution.
This can leave hidden content and persistent animation work on media failure.
It is a source-level finding, not an established explanation for the recording.

Recommendation implemented: configurable bounded capture steps with explicit
incomplete notices, comparison of recordings against sectional images, and
visible poster/DOM fallback until the renderer has actually produced a frame.
Failed loads must leave pending animation work and late callbacks must respect
disposal. Historical testbed source and verdicts were not rewritten.

### 6. Some guidance still conflicts or promotes ritual

The Recommended CLI configuration singled out sourced/licensed images while
the core planning prose allowed best-fit sourced or generated material. Visual
refinement also demanded a perceptible before/after change even if inspection
found nothing to fix. Neither is useful direction for a capable agent.

Implemented: aligned the material configuration; replaced compulsory cosmetic
change with correction when observation finds a real defect or brief mismatch.
Kept build checks, installation integrity, runtime regression tests and honest
limits on what those checks prove.

## Production capability delivered

`dreative media-inspect` accepts a local video, still, or directory of stills.
It produces a contact sheet, a labeled HTML index and JSON metadata using local
FFmpeg/ffprobe. It bounds samples and video duration, refuses existing output,
preserves source bytes, executes without shell interpolation, and rejects
nonvisual/error-page input. It does not download assets or infer their rights.

This removes repeated work needed to compare material or inspect a suspect span
of footage. It does not solve art direction automatically. The generated
[material sheet](.dreative/audit-20260908/material/contact-sheet.jpg) and
[recording samples](.dreative/audit-20260908/desktop-opening/contact-sheet.jpg)
were opened during this audit. These local ignored outputs are inspection aids.

For reference implementation, added targeted paths to
[Codrops image/typography expansion](https://tympanus.net/codrops/2024/04/02/on-scroll-expanding-image-animation-within-typography/),
[GSAP Flip](https://gsap.com/docs/v3/Plugins/Flip/) and
[GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/).
These support specific transition and responsive ownership decisions; no claim
is made that their demos establish a complete site's quality. The media command
uses [FFmpeg's documented filters](https://ffmpeg.org/ffmpeg-filters.html).

Keep advanced production conditional: footage for temporal material, image
generation/editing for coherent invented shots, Blender for controllable
geometry/camera/light, and GSAP/Motion/OGL/Pixi/Rive for the behavior they actually
enable. A provider name, installed runtime or recommended plugin is not proof
of a callable asset-authoring pipeline. No new paid service or plugin was needed
for the changes here.

The new guidance remains proposed. Freeze aaba0cf and the resulting revision,
then compare complete outputs with the same host/model/tools/budget on held-out
motion-led and ordinary tasks. Do not change the skill between arms. Include
truncations, completion time/cost, and normal desktop/mobile playback. Judge
material, middle, primary task, and ending separately from the opening. Repeat
before making a broad claim; one better prototype does not validate the route.

Keep the existing native foundations. They solve real lifecycle and responsive
mechanics and already have behavioral tests. Do not add a giant effect library,
mandatory critic agents, more read-count gates, or automatic taste scores.
Showcase's legacy tracked-contract/Experience Map burden remains a separate
compatibility issue; this Recommended run did not exercise it, so it is not a
supported explanation for this result.
