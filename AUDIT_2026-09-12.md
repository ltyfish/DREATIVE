## Findings and implemented corrections

### 1. The protocol reinforced the isolated hero

Whole-route guidance was undermined by a testbed prototype prompt that forbade
other sections, required already-treated assets, and froze the hero anchor.
Approval of that slice then encouraged expansion around it rather than testing
its real destination.

Updated `scripts/lib/prototype.mjs` in the adjacent testbed: plan the complete
direction, prototype the hardest passage with its real receiving interaction,
then expand unresolved parts of the experience. The existing user prototype
review remains. Successful mechanism code is retained; joins can adapt. This
protocol change affects both arms and is an experimental variable.

### 2. Asset fallback became the product

The latest Claude run spent effort refining procedural material while lacking a
usable garment view. Tool discovery and failed stock access were treated too
broadly as exhausted sourcing.

Updated material and resource guidance to discover the relevant generation
capability explicitly and resolve one usable subject view before producing a
whole set. An ambitious bespoke mechanism now begins with study of a relevant
live passage and its actual source/material, then adapts to the current subject.
This does not mandate a provider, paid service, video, 3D, or a fixed visual style.

### 3. Motion guidance needed composition support, not more quotas

Aligned the skill, plan, motion routing and CLI delivery instructions around the
whole experience before selecting the focal effect. Removed fixed option counts,
a compulsory post-hero peak and mandatory continuity-primitive choices. Distinct
events should answer the brief; changing crops or filters alone is not evidence
of a varied route.

Added `motionTrack(stops)` to the native runtime for deterministic numeric tracks:
overlapping intervals, repeated-value holds, easing and reverse traversal.
Documented an example with independently timed typography and aperture changes.
It is a composition helper, not a new effect catalogue or quality gate.

### 4. Native mechanisms had concrete lifecycle and progress defects

- Sticky chapters now use the actual pin interval by default, rather than the
  broader viewport-passage interval. The lower-level sampler retains passage as
  its default and supports explicit `range: "pin"`.
- Kinetic type waits for viewport entry by default; mounting offscreen no longer
  spends its animation before it can be seen. Immediate mount remains opt-in.
- Resize/font refresh, live reduced-motion changes, disposal and explicit refresh
  are handled. Reduced-motion chapters expose their content.
- Spatial galleries place the selected/nearer item above distant items.
- The executable demo now fits mobile video, provides hover/focus feedback and
  avoids a crowded header label.

### 5. Some smoke failures punished valid motion or missed real controls

Updated browser sampling to use the document body when there is no `main`.
Separated CSS reveal-state changes from sticky position changes so readable pins
are not treated as late entrances. Text-collision checks compare rendered text
ranges instead of entire card/button surfaces, allowing overlapping surfaces
with separate labels. Regression fixtures still catch actual late reveals and
text collisions.

These remain bounded DOM checks, not glyph-ink analysis or a verdict on taste.

### 6. Archives concealed capture/source mismatch

The testbed now fingerprints captured source/media/package inputs, records the
capture phase, and compares them with archived inputs. The archive page displays
matching, different-source, changed-during-capture or unknown correspondence and
an incomplete-run notice where applicable. Old captures remain unknown when no
evidence exists; their provenance is not invented retroactively.

The fingerprint deliberately excludes secrets, logs, captures and dependencies.
It is source correspondence, not a guarantee of identical build environments.

## Reference study

The [Codrops typography/image expansion study](https://tympanus.net/codrops/2024/04/02/on-scroll-expanding-image-animation-within-typography/)
and its [live demo](https://tympanus.net/Development/ImageExpansionTypography/)
provide a useful concrete example of composing different layout endpoints.
The [original MIT-licensed source](https://github.com/codrops/ImageExpansionTypography)
captures a final layout state and interpolates into it, rather than relying on an
image filter to supply the event. This is a reference to adapt, not a prescribed
Dreative style. No source code from it was copied into the new track sampler.
The [official ScrollTrigger documentation](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)
was consulted alongside the local runtime audit.
