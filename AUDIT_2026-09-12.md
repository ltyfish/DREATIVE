## Findings and implemented corrections

### 1. The protocol reinforced the isolated hero

Whole-route guidance was undermined by a testbed prototype prompt that forbade
other sections, required already-treated assets, and froze the hero anchor.
Approval of that slice then encouraged expansion around it rather than testing
its real destination.

Updated `scripts/lib/prototype.mjs` in the adjacent testbed: plan the complete
direction, prototype the hardest passage with its real receiving interaction,
then expand unresolved parts of the experience. The existing user prototype
review remains. Successful mechanism code is retained; joins can adapt. This
protocol change affects both arms and is an experimental variable.

### 2. Asset fallback became the product

The latest Claude run spent effort refining procedural material while lacking a
usable garment view. Tool discovery and failed stock access were treated too
broadly as exhausted sourcing.

Updated material and resource guidance to discover the relevant generation
capability explicitly and resolve one usable subject view before producing a
whole set. An ambitious bespoke mechanism now begins with study of a relevant
live passage and its actual source/material, then adapts to the current subject.
This does not mandate a provider, paid service, video, 3D, or a fixed visual style.

### 3. Motion guidance needed composition support, not more quotas

Aligned the skill, plan, motion routing and CLI delivery instructions around the
whole experience before selecting the focal effect. Removed fixed option counts,
a compulsory post-hero peak and mandatory continuity-primitive choices. Distinct
events should answer the brief; changing crops or filters alone is not evidence
of a varied route.

Added `motionTrack(stops)` to the native runtime for deterministic numeric tracks:
overlapping intervals, repeated-value holds, easing and reverse traversal.
Documented an example with independently timed typography and aperture changes.
It is a composition helper, not a new effect catalogue or quality gate.

### 4. Native mechanisms had concrete lifecycle and progress defects

- Sticky chapters now use the actual pin interval by default, rather than the
  broader viewport-passage interval. The lower-level sampler retains passage as
  its default and supports explicit `range: "pin"`.
- Kinetic type waits for viewport entry by default; mounting offscreen no longer
  spends its animation before it can be seen. Immediate mount remains opt-in.
- Resize/font refresh, live reduced-motion changes, disposal and explicit refresh
  are handled. Reduced-motion chapters expose their content.
- Spatial galleries place the selected/nearer item above distant items.
- The executable demo now fits mobile video, provides hover/focus feedback and
  avoids a crowded header label.

### 5. Some smoke failures punished valid motion or missed real controls

Updated browser sampling to use the document body when there is no `main`.
Separated CSS reveal-state changes from sticky position changes so readable pins
are not treated as late entrances. Text-collision checks compare rendered text
ranges instead of entire card/button surfaces, allowing overlapping surfaces
with separate labels. Regression fixtures still catch actual late reveals and
text collisions.

These remain bounded DOM checks, not glyph-ink analysis or a verdict on taste.

### 6. Archives concealed capture/source mismatch

The testbed now fingerprints captured source/media/package inputs, records the
capture phase, and compares them with archived inputs. The archive page displays
matching, different-source, changed-during-capture or unknown correspondence and
an incomplete-run notice where applicable. Old captures remain unknown when no
evidence exists; their provenance is not invented retroactively.

The fingerprint deliberately excludes secrets, logs, captures and dependencies.
It is source correspondence, not a guarantee of identical build environments.

### Independent findings

1. **Verified: the active installation was stale.** The initial
   `node dist/cli/index.js install-skill --codex --check` exited 1 and listed
   18 stale files. Installed SKILL.md prescribed the old direction/configuration
   gates while source SKILL.md prescribed generated visual selection. A fresh
   source commit did not imply the builder would receive its instructions.
   Whether this affected the user's latest run remains unknown without that run's
   installed tree or transcript. Refreshed the local Codex installation.

2. **Verified: installation verification missed package additions.**
   `src/cli/installSkill.ts` derived its expected set solely from the installed
   manifest. A new reference at an unchanged package version could be absent while
   every old hash remained valid. The check now compares the current packaged set
   as well. A regression test uses an otherwise intact old install, adds one
   shipped reference, and verifies failure followed by successful reinstall;
   unselected specialists and maintainer-only material remain excluded.

3. **Verified guidance gap; outcome effect unproven:** the visual-selection stage
   began with generation while explicit choreography research could happen later.
   A still could therefore fix the page's composition before the intended motion
   was resolved. PLAN.md, VISUAL_DESIGN.md, SKILL.md and CLI guidance now place
   concept, actual content, material, motion endpoints and feasibility before
   generation. There is no added approval gate or mandatory planning schema.

4. **Verified example gap:** the existing `systems/demo.html` explicitly presents
   isolated functional fixtures, including solid-color sequence frames, a square
   handoff and a source-less video fallback. These exercise mechanics; they do not
   demonstrate translating an image-led concept into an authored usable passage.
   Added three original executable graphic studies with worked generation briefs:
   typography into programme, selected edition into reading room, and controlled
   print registration. These expand the examples without replacing the primitive
   tests or prescribing a shared page style.

5. **Verified limit of automation:** smoke tests explicitly permit an otherwise
   healthy route where nothing moves. Finalization is command/defect evidence,
   not evidence that the requested motion is good or even fully represented.
   Restoring an arbitrary motion quota would repeat the historical enforcement
   loop. Inspect the agreed event in playback and its actual destination instead.

6. **Verified memory drift:** vault state was dated September 7 and described
   old machine paths and next steps. It could not reliably establish today's
   source revision, install state or completed evaluation. Current state is now
   recorded separately from unverified historical testbed claims.

### Illustrative generation and its limits

Generated one three-state fictional print-exhibition storyboard using the built-in
image tool, then edited that same image to remove invented venue, dates and
supporting copy. The second output preserves the principal title and programme
content. These are proposed compositions, not video frames or a selected client
implementation. The live lab was authored separately; it is not a faithful
implementation of the generated storyboard. It demonstrates bounded interaction
relationships and does not validate generated-to-code fidelity.

The graphic studies deliberately require no external imagery or dependencies.
That makes them portable, but leaves photography, footage, 3D, real inventory
fidelity and low-end device performance untested by these additions.

### Verdict and improvement order

Dreative has substantial available motion mechanics. The stronger diagnosis is
an unreliable path from the current instructions and a chosen composition to
observed execution. More generations alone will not establish that this path
works. First use the current verified install; then plan the actual visual event
before generating; preserve the selected composition in a full-fidelity slice;
compare that slice and its receiving region in the browser before funding the
rest of the route. Use the weakest downstream passage to direct remaining work.

The patches fix a concrete distribution defect and make planning/examples more
useful. Their effect on complete generated websites is still unproven. The next
meaningful evaluation is a complete run with fixed brief, model/tools and budget,
recorded source revision, normal-motion desktop/mobile review, and an external
verdict. Include one unfamiliar subject before generalizing. Do not declare the
loop solved from the new fixtures or this audit's own report.
